# 开发须知

产品功能与启动方式见 [README](../README.md)。这里是改代码时用得上的东西。

## 两部分，各管各的

| | 负责 | 不负责 |
| --- | --- | --- |
| **skill**（大模型 + 提示词） | 判断哪里值得去、为什么、玩什么 | **不给坐标、不给距离、不给营业状态** |
| **高德** | 坐标核实、直线距离、营业状态、路径规划 | 不参与推荐 |

这个分工是刻意的：提示词里明写「没接地图 API 时算不准，给一个错的数字比不给更糟」。
所以距离和路线一律由高德算。

**只有高德核实通过的地点才能上图、才能参与路线。** 核实不到的会保留在列表里并标注
「高德未能核实」——它可能只是高德没收录，丢掉等于拿我们的短板惩罚用户。

## 环境变量

| 变量 | 用途 | 是否进浏览器 |
| --- | --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 服务端调地理编码、周边搜索、路径规划、天气 | 否 |
| `AMAP_JS_KEY` | 浏览器渲染地图 | 是（靠高德控制台域名白名单保护） |
| `AMAP_JS_SECURITY_CODE` | 配合 JS API | 否（走 `/_AMapService` 代理） |
| `AMAP_MAX_CONCURRENCY` | 同时在飞的高德请求上限，默认 3 | 否 |
| `DEEPSEEK_API_KEY` | 服务端调 skill | 否 |
| `DEEPSEEK_MODEL` | 模型 ID，**用 `npm run models` 确认后再填** | 否 |
| `ROUTE_PROVIDER` | `amap` \| `mock` | 否 |
| `RECOMMEND_PROVIDER` | `mock` \| `skill` | 否 |
| `RECOMMEND_VERIFY` | `amap` \| `mock`，核实层。**目前不在 `.env.example` 里** | 否 |
| `RECOMMEND_WEATHER` | `amap` \| `mock` | 否 |
| `WEATHER_OVERRIDE` | 只在 `RECOMMEND_WEATHER=mock` 时生效：`storm` \| `cloudy` \| `sunny` | 否 |

全部只从 `.env.local` 读，**任何值都不要写进仓库**（`.env.example` 里只有变量名）。
`AMAP_JS_KEY` 会进浏览器，所以类型必须是高德的「Web端(JS API)」，
并在控制台配好域名白名单。

**`AMAP_JS_KEY` 为什么没有 `NEXT_PUBLIC_` 前缀**：Vercel 的环境变量面板不接受那个名字
（报「变量名是保留字」）。送进浏览器的路径改由 `next.config.ts` 的 `env` 段承担 ——
Next 文档说这个段里的值「always be included in the JavaScript bundle」，不看前缀。
少了前缀**不等于**它变保密了：它照样进浏览器产物，保护它的仍然只有域名白名单。
代价与 `NEXT_PUBLIC_` 一样是**构建期内联**，改了要重新部署才生效。

## 天气层

**天气由平台实测后再喂给 skill，不由它自己查。** skill 没有任何可用工具，
让它「查天气」等于让它凭记忆编。所以：

- 输入里加一行「天气（平台实测，更新时间 …）」。取不到就**整行不给**，而不是写
  「天气未知」——空更能触发提示词里「没有这一行就别据此调整」那条规则，
  写「未知」反而可能诱导它补一个
- 取天气失败返回 `null` 而不抛：拿不到天气不拦推荐，只是那条天气行不发
- 提示词里有一条硬规则：天气只能用平台给的实测行，没有就照常推荐，
  并在 `meta.assumptions` 里声明「天气未知，室内外未据此调整」

`RECOMMEND_WEATHER=mock` 配 `WEATHER_OVERRIDE` 可以在不耗高德额度的情况下调天气界面。

`/sky` 是天气层的预览页（不参与任何业务流程）：把 8 种天气 × 昼夜共 15 个态一次摆开，
每一格都是**等比缩小的真实视口**，渲染的是首页那**同一个** `WeatherOverlay` 组件 ——
没有平行实现、没有降级分支。所以在这里看到的构图就是首页会画出来的构图。

## 几个必须知道的坑

- **坐标系**：浏览器定位给 WGS-84，高德用 GCJ-02，国内差 100~700 米。
  不转换不是「标记画歪」，而是 **skill 按偏了的位置检索，推荐出一批别处的地方**。
  地图选点的坐标已经是 GCJ-02，**再转一次会转坏**，所以转换严格绑定坐标来源。
- **直线距离不是驾车距离**。列表上标的是直线距离，界面必须写明「直线」；
  真实里程只有规划出路线之后才有。
- **出行方式是逐段定的，不是整条一种**。高德没有跨方式的路径规划接口
  （每种方式一个地址，没有「逐段指定方式」这种参数），所以「两个地方太近就别坐地铁」
  只能在本地做：按段的**直线**距离定候选（步行 ≤1 km、骑行 ≤5 km、更远公共交通→自驾），
  第一候选算不出来才换下一个，且只影响这一段。
  **不要改成「按高德返回的时长挑最短」** —— 它的时长是机械时间，不含等车之外
  （634 米的公交方案 25 分钟）、也不含骑行要停车、走路会累。按时长排序的结果是
  8 公里内每段都选骑行、10 公里内每段都自驾，「地铁优先」会被整个吃掉。
- **高德按秒限流**（`CUQPS_HAS_EXCEEDED_THE_LIMIT`），与月度配额是两回事。
  连点会造成请求风暴，所以路线请求有 400ms 防抖。
- **高德用 `[]` 表示空字段**，很多字段也不保证是字符串。所有字段读取统一走
  `lib/core/coerce.ts` 的 `asText()`，不要在调用点直接做字符串操作。
- **任何 `catch` 都不许静默吞错**。上一轮正因为 `catch` 吞掉限流错误，
  一个失败被伪装成了「0 分钟 0.0 公里」的路线。

## 提示词

放在 `lib/recommend/prompt.md`。文件头部的注释列了模型的硬要求和输出形状。

注意：**提示词里必须出现 "json" 字样并给出输出样例**，否则模型可能一直生成
空格直到撞上 `max_tokens`，表现就像请求卡死。

## 测试

```bash
npm test
```

33 个文件 315 个用例。

**纯逻辑**（`lib/core`、`lib/recommend`、`lib/providers`，跑在 node 环境）：
坐标转换、模型响应解析（含流式）、增量 JSON 提取、skill 输出结构校验、
diff 应用（同名 upsert 与子点层匹配）、选择继承、顺序优化（含固定终点）、
出行时间轴、出行方式的逐段选择（按距离定候选、逐段独立换候选）、高德请求的并发闸门、
公共交通返回体的解析、营业状态解析、地址模糊化、地理计算、天气的归类与描述。

**组件与页面**（`components`、`app`，文件头用 `// @vitest-environment jsdom` 单独切换）：
- `RecommendList` —— 细化按钮的显示条件、细化说明的数字、分组、追问新增的归属、未核实标注
- `RecommendCard` —— 档位高亮判据、复合地点提示、未核实不可勾选、距离标「直线」
- `TripTimeline` —— 分段渲染、混用方式时逐段各显示自己的方式、降级提示、终点行、且不出现任何时刻
- `SelectionTray` / `ViewSwitch` / `PlaceCardSkeleton` —— 下一步入口的显示条件与状态同步
- `app/plan/page` —— 流式逐条渲染、细化后的继承与按钮消失、**中途失败后重试跑对任务**、
  地图上不再出现「1→2→3」顺序卡（两个视图都不出现）

组件测试存在的理由：有一轮修了三个 bug，**两个是用户点出来的、一个是我事后审计出来的，
没有一个被测试拦住**。它们全是同一形状的「从派生状态反推用户意图」。
新加的这批测试都做过变异检查（把 bug 塞回去确认测试会红），不是摆设。

另有一项契约测试（`skill-contract.test.ts`）把 skill 的文档与样例喂给平台真实解析器，
路径不存在时自动跳过。跑法见该文件头部注释。

**不测**：真实模型调用、高德真实接口、地图渲染（jsdom 里跑不起高德 JS API，
测试里把 MapCanvas 整个 mock 掉了）—— 这些靠手工验收。
